# Thunderbird: U+10000 is encoded as three bytes of invalid UTF-8

thunderbird/thunderbird-android `main` at 6987473, module `mail/common`.

## The survivor

```
src/main/java/com/fsck/k9/mail/helper/Utf8.kt:96  CONDITIONALS_BOUNDARY  SURVIVED
    codePoint < 0x800 → codePoint <= 0x800
    tests: MimeParameterEncoderTest.longParameterValueWithNonAsciiCharacters
```

## What it exposed

The survivor, and two more on the same function, say that no test pins which code points go to which
branch of `Int.encodeUtf8`. Reading the branches, the three-byte one covers `0xe000..0x10000`, which
includes U+10000. That code point needs four bytes, and `utf8Size` in the same file says so. The
encoder writes `F0 80 80` instead, which is not valid UTF-8. It is used when a long attachment name
is split over several header lines, so such a name that contains U+10000 reaches the recipient
garbled. Only this one code point is affected. The fix ends the range at `0xffff`.

## Files

- `utf8-u10000.patch`: the fix and a test in `MimeParameterEncoderTest` that encodes and decodes a long
  name with U+10000. It fails on `main` (the name comes back as replacement characters) and passes
  with the fix. The rest of `:mail:common:test` (334 tests) passes.
